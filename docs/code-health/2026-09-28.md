## Summary

The codebase is healthy. It keeps its own hard rules almost everywhere:
- gameplay reads `Time.deltaTime` nowhere but `TickEngine`
- no static state beyond `GameText`
- no `Find` calls or legacy Input
- no balance numbers in rules
- nothing assumes seven pools
- `LoopState` and `PersistentState` stay apart
- event subscriptions are symmetric

The UI improved a lot since yesterday: 0 🔴 (was 3), and 10 of the earlier 🟠 are fixed or gone with the retired panels.

The three 🔴 are small and contained:
- a save loses which item a pick-up was for
- room titles read "The Smoky Mirror" mid-sentence in three refusal reasons
- an editor window re-ticks labels the user unticked

The biggest themes:
1. **Save coverage has gaps.** The round-trip tests check only some fields, which is how the 🔴 save bug went unnoticed.
2. **Core repeats its own rules.** The "real gives" filter appears 7 times, the container fill order twice, and neighbour-finding twice. "Which verb is this" is tested in six places.
3. **Silent failures linger.** The save loader drops unknown hues and pools without a warning, "Saved" shows even when the write failed, and error messages point to retired setup steps.

## Fix now (🔴)

1. **A saved run loses which item a pick-up or put-down was for** · `Assets/Scripts/Core/Saving/SaveSerializer.cs:132-133`, `:207-212` · §5 / CLAUDE.md saves
   - **Problem:** pick-ups, put-downs (and trips) are copies of one verb and share its Id (`Simulation.Floor.cs:91-100`). `CompletedTasks` and `CompletionLog` save only `t.Id`. On load, `Find<TaskDefinition>` returns the bare verb, so a resumed run's report merges "Pick up the tome" and "Pick up the phial" into one "Pick up ×2" line. A future `oncePerRun` floor action would also check the wrong task.
   - **Fix:** a failing test first (in `RunSaveTests`: pick up two items, save, resume, compare `LastRun`). Then save these lists as `{task, item, destination}` entries, reusing the queue's verb-plus-item rebuild. Bump `SaveData.CurrentVersion` with an upgrade step: old saves keep the bare verb.
   - **Effort:** S–M
2. **Room titles are capitalised mid-sentence in three refusal reasons** · `Simulation.Tasks.cs:552`, `Simulation.Reorder.cs:111`, `Simulation.Places.cs:134` · content.md "Room names mid-sentence"
   - **Problem:** `GameText.Get("reasons.not_here", ("room", room.DisplayName))` shows the player "can't be done at The Left Corridor" and "no way from The Smoky Mirror". The trip reason next to it (`Tasks.cs:70`) already does it right.
   - **Fix:** wrap each in `GameText.TitleInSentence`. Fold in the backlog's `reasons.fully_explored` item (`Offers.cs:23`, `Exploring.cs:46`), which is the same fix.
   - **Effort:** S
3. **Scene Labels window re-ticks labels the user unticked** · `Assets/Editor/SceneLabelsWindow.cs:41`, `:119` · §4 / bug
   - **Problem:** `private void OnFocus() => Find();`, and `Find()` sets `label.Ticked = true` for every movable label. Untick a label, click into the Hierarchy, click back, and it's ticked again. "Move N ticked" then appends its words to `game_text.txt` and adds a Text Key to a label that code writes. Undo removes the component but not the file lines.
   - **Fix:** don't rebuild on focus (only in `OnEnable` and on Refresh), or keep the ticks across a rebuild in a `Dictionary<TMP_Text, bool>`.
   - **Effort:** S

## Good patterns to keep

- **Side-by-side save test** (`RunSaveTests.cs:89`): run the original and the reloaded game together for 20 seconds and compare field by field. It is the strongest check the project has; top refactor 1 extends it rather than inventing something new.
- **"The UI finds the gap, Core decides"** (`QueueDragController` with `CanMoveEntry`/`CanMoveStop`; `PriceOf` as the single price for charging and display). The UI holds the dragged `QueueEntry` itself rather than an index and only shows what Core allows, with a reason. Every new interaction should copy this.
- **One list, enforced by a test** (`ItemSections.All`, which feeds both the item Inspector and the Balance Sheet; `ItemSectionsTests` fails if a new field isn't placed). Also atomic saves (`SaveSlots.cs:31-36`: write a temp file, then replace), so a crash mid-save can't corrupt a slot.
