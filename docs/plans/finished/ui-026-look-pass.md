# UI 026 — Look pass: backdrop and vignette, one top strip, clean captures, pathos facets

**Status:** Done (2026-09-30). The bar was kept; facets deleted and parked for the art pass.
**Design:** GDD §13a; `docs/mockups/main-screen/composition-critique.md`; `docs/UI-BACKLOG.md` *Now*; decisions-log 2026-09-29 *Queue column built*, *UI colour roles*. Replaces `ui-014-main-screen-look.md`, which was written before the queue column, colour roles and popover placement were built.

## Goal
A screenshot of the main screen shows a place, not a tool: a dark backdrop with a vignette behind the map, one slim top strip, and no overlapping panels. The player can also try the pathos display as seven small facets and the user can judge it against the rainbow bar. Nothing about how the game plays changes.

## Out of scope
- **The vignette that creeps in as vitality drops**: parked in `docs/UI-BACKLOG-later.md`. Build the static vignette so its strength is one number on `MapStyle`, nothing more.
- Vitality-as-star-bar (amber to red), colour as the payoff, Clara on screen, juice, ghost of last run, tooltip redesign, Button/Chip prefabs: still in the backlogs.
- The dev panel: left as it is (the user's call), so screenshots are taken with F1 or backtick pressed.
- Real painted backdrop art (a later, licensed asset).
- **Already built, so not planned again:** popover beside its node (`PopoverPlacement.LowerLeft`), no bottom queue strip (ui-019), one panel material (plan 012's colour roles; no wood-grain asset exists any more).

## Design assumptions
- **Placeholder rule:** the backdrop is a generated dark gradient with a generated radial vignette, so nothing to license and no Steam AI disclosure. They are one image slot each, swapped for real art later.
- The map already takes about 60% of the width and 93% of the height at 1920×1080 (Story 400 px, Queue column 360 px, top bar 7%). Step 1's screenshot confirms it; **no resize is planned** unless it shows a problem.
- "Only one of popover and tooltip at a time" (the old plan) would hide the popover's own tooltips (floor chip, searched bar, ways), so it is dropped. The overlap that actually shows in captures is a tooltip covering the notice toast (`2026-09-29-tooltip-covers-notice.png`): the fix is that a tooltip is placed clear of the toast. **This changes what the player sees; approving the plan confirms it.**
- The speed tiers (×1, ×2, ×3) become part of the header row, not a second strip, so the top bar is one strip even once a faster speed is earned.
- **Placeholder rule:** the facets are seven small diamonds, dark when the pool is empty and filled in its hue as it fills, replacing the rainbow bar's slices. The switch between the two displays is a toggle on the dev panel, remembered in PlayerPrefs, so players never see it. The user judges both, then the choice is logged and the loser deleted.

## Steps
1. Screenshot the current main screen at 1920×1080 and 1280×800 into `docs/mockups/main-screen/` as `YYYY-MM-DD-before-look-pass-*.png` (dev panel hidden with F1). Confirm the map's share of the frame; note any clipping.
2. Write failing EditMode tests for the tooltip placement (clear of a rect) and the facet fills.
3. Implement the tooltip placement helper and wire `ToolTipPanel` to it.
4. **Step 96, part 1:** generate the backdrop and vignette images and add them under the map; `MapStyle` fields; check clicks still pass through both images. Screenshot.
5. **Step 96, part 2:** move the speed tiers into the header row; remove the second strip. Check with a faster speed earned and not earned.
6. `PoolBars` facets mode and the dev-panel toggle.
7. Play at both resolutions: nothing clipped or overlapping (popover open, tooltip over the toast, pockets overlay, node labels). Screenshot after. The user judges the shots against the before shots and picks bar or facets.
8. Logging: decisions-log (composition confirmed, backdrop/vignette as placeholder, tooltip rule, facets verdict); delete the losing pathos display; update `docs/mockups/README.md`; move finished items out of `docs/UI-BACKLOG.md`; `/sync-state`.
